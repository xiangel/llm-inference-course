# 第 14 章 · 毕业项目

**学时** 按选题 · **需要** Git、Python；选题 B 需要真实 GPU · **本章没有** Colab

一句话回答：**怎样把“我读懂了”变成可复现、可评价的推理工程成果？**

## 为什么

推理系统的结论很容易被一次偶然运行误导。毕业项目要求明确问题、固定条件、保留证据并说明限制。目标不是复刻整个 vLLM，而是完成一个边界清楚、能被他人复查的工程作品。

## 心智模型

把项目当作一份小型工程 RFC：输入和约束在前，设计和实施居中，测量与失败案例在后。每个“更快”“正确”或“更省显存”的断言，都要有对应的基线、方法和原始结果。

## 数据流建议

根据选题复用已有组件：选题 A 用 <code>&lt;RequestLifecycleFlow /&gt;</code> 标记队列与每轮调度；选题 B 用同一图标出测量点（到达、首 token、完成）；选题 C 用第 10 章的 <code>&lt;KvCacheFlow /&gt;</code> 标出 block pool 与 cache manager。图服务于说明证据链，不需要新增组件。

## 选择一个有边界的题目

### A. CPU mini 推理调度器

实现一个不含真实模型的 Python 模拟器：请求具有到达时间、prompt token、目标输出长度；调度器支持 waiting/running、连续批处理、token budget 和固定大小 KV block pool。输出每 tick 的调度记录、完成时间、空槽和块使用量。

**验收：**至少三个确定性工作负载；一个展示静态批处理浪费；一个展示块回收；一个展示容量不足的安全拒绝/等待。单元测试覆盖“完成请求不再调度”和“共享块未被过早释放”。不要求 GPU。

### B. 单机 vLLM SLO 实验报告

在真实、受支持的 NVIDIA GPU 上，用第 8 章方式运行 vLLM。固定模型 revision、vLLM 版本、GPU、输入集、最大输出、并发和预热方式；比较至少两种明确配置（例如并发或上下文预算），记录 TTFT、ITL、吞吐、显存/缓存相关指标和失败。

**验收：**可执行命令或脚本、原始 CSV/JSON、图表、方法说明和结论边界。GPU 型号、驱动和显存是报告的一部分。没有 GPU 时不要伪造结果，改选 A 或 C。

### C. vLLM V1 源码路径说明

基于固定 vLLM commit，写一篇面向 Python 工程师的调用路径导览：从 `vllm/v1/engine/llm_engine.py`、`v1/request.py` 到 `v1/core/sched/`、`core/kv_cache_manager.py`、`block_pool.py`。用一条请求解释状态、调度决定、KV 准入与回收如何衔接，并链接关键测试。

**验收：**职责图、至少五个带 permalink 的源码引用、一个跨文件追踪表、两个版本/实现可能变化的注记。不要写“第 N 行永远如此”的说法。

## 有序实施

1. 写一段问题陈述：用户、负载、约束和不做什么。
2. 固定版本、随机种子（适用时）与输入数据；清除敏感提示词和密钥。
3. 定义成功标准和失败标准，再实现最小路径。
4. 先跑基线，保存原始输出；再只改变一个变量。
5. 添加自动测试或可重复运行脚本，记录环境与命令。
6. 写结论时同时报告有效结果、失败样例和不能外推的范围。

## 评分量规

| 维度 | 分值 | 达标证据 |
| --- | ---: | --- |
| 问题与范围 | 20 | 目标、约束、非目标清楚且可完成 |
| 技术正确性 | 25 | 生命周期、调度或测量的解释与实现一致 |
| 可复现性 | 20 | 版本、命令、输入和环境记录完整 |
| 证据与评估 | 25 | 有基线、指标/测试、原始结果和限制 |
| 工程表达 | 10 | 结构清楚，错误路径与取舍可读 |

总分 70 分及以上为通过；任何伪造硬件数据、无法复现的“性能提升”或泄露密钥的提交都不通过，必须先修正。

## 生产连接

选题 B 的服务与安全基线见 [vLLM 文档](https://docs.vllm.ai/en/latest/)；选题 C 的主来源是 [vLLM 仓库](https://github.com/vllm-project/vllm)。现实生产部署还应有访问控制、限流、可观测性、模型许可审查和事故响应；项目报告应明确哪些没有覆盖。

## 常见误解

- 项目越大不代表越好；可验证的狭窄范围更有价值。
- “GPU 利用率高”不是唯一成功指标，质量和尾延迟同样重要。
- 一个成功截图不是实验；需要命令、条件和原始结果。
- 源码说明不能用过期分支或无 permalink 的模糊链接充当证据。

## 小结

- A 练调度与内存生命周期，B 练真实服务测量，C 练生产源码阅读。
- 先定约束和基线，再用可复现证据得出结论。
- 如实报告硬件、失败和限制，是工程质量的一部分。
