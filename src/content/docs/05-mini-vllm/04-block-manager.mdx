## 本章目标

本章解决的问题：**4.5 的块表，在数组上怎么写？**

读完应能：说出 `k,v` 的三维形状；用 `divmod` 解释第 $i$ 个 token 落在哪一页；区分 `free` 方法与 `free_ids` 列表。

---

## 1. 代码实现

池子：

```text
k, v : [num_blocks, block_size, hidden]
free_ids : 还没借出去的页号
```

早期草稿用 `self.free` 当列表，结果把 `free()` 方法盖住了。测试会在结束请求时炸掉。现在列表叫 `free_ids`，方法叫 `free(req)`。这是一则真实的命名课，不是闲笔。

`ensure(req, target_len)` 按 $\lceil L/\mathrm{block\_size}\rceil$ 补页。`write_kv` 从 `start_index` 连续写入。`gather_kv` 按逻辑下标再拼回 `[S, H]`。

Attention **看不到页**。ModelRunner gather 完再调用 `ToyLM.forward`。所以：

:::tip[💡 核心概念]
Mini-vLLM 的分页证明的是**分配与回收**，不是 PagedAttention CUDA kernel。
:::

---

## 2. 正确性

`test_write_gather_roundtrip`：写入 `arange`，gather 必须相等；`free` 之后 `free_ids` 回到满员。数值错了就是页表错了，不要用“近似”搪塞。

`hidden` 在教学模型里等于全部注意力宽度（单头）。生产里还要乘层数、头数；本引擎只有一层、一个头，公式仍是 2.5 的缩小版。

---

## 3. 本章小结

1. 三维池子 + 块表 + `divmod`。
2. gather 保数学，页表保容量。
3. 命名不要让资源和释放函数撞车。
4. 下一节：谁来 gather 并跑 forward。
