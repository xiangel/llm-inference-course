## 本章目标

本章解决的问题：**怎样用这个玩具度量“第一字”和“之后每字”，同时不把它说成基准测试？**

读完应能：用 `demo_tpot_steps` 解释 prefill_steps 与 decode_steps；列出非目标清单；知道第六篇从哪里接着讲。

---

## 1. 步数不是毫秒

`demo_tpot_steps` 数的是 **schedule 次数**：

- `prefill_steps`：直到（并包括）产出第一个输出 token 的 Prefill 块数。切块越碎，这个数字越大，TTFT 在真实系统里通常越差。
- `decode_steps`：之后的 Decode 次数。教学里它等于 `max_new_tokens - 1`（第一个 token 在 Prefill 结束时采样）。

例：Prompt 长度 5，`max_prefill_tokens=2`，`max_new_tokens=3` → prefills ≥ 3，decodes = 2。见 `tests.test_mini_vllm.EngineTests.test_chunked_prefill_uses_several_steps`。

这些是**结构计数**。把它们写成 “TTFT=3 ms” 是造假。真实 TTFT/TPOT 要在 GPU 上对墙钟计时，并写清模型、卡、batch、长度、精度（第十三篇）。

:::tip[💡 核心概念]
教学指标回答“经过几段活”，生产指标回答“用户等了多久”。前者用来验状态机，后者用来验 SLA。
:::

## 2. 有什么 / 没有什么

| 有（教学） | 没有（请到后文或生产引擎） |
| --- | --- |
| 自回归 Prefill / Decode | 真实权重与 Tokenizer |
| FCFS + 切块 + 连续组批 | Hybrid kernel、CUDA Graph |
| 分页分配 / 回收 | PagedAttention CUDA、Prefix Cache |
| 贪心与流式 | 完整 Sampler、stop、工具调用 |
| 单进程 NumPy | 多卡、量化、前缀复用、抢占 |
| 步数计数 | 可发布的 token/s |

身份再写一次：**Mini-vLLM 是这本书的教具。vLLM 是生产项目。** 第六篇对照 V1 的模块边界时，会列出“多出来的是工程，不是另一套数学”。

## 3. 前五篇收束

主链已经从“一个 token 怎么来”走到“一个能同时服务多人的教学引擎”：

**token → Prefill/Decode/KV → GPU 屋顶线 → 调度与分页 → Mini-vLLM。**

还没讲的：生产 vLLM、手写 kernel、量化、切卡、引擎选型、投机与 PD 分离、网关与容量、万卡。目录在 [后续篇章](../../later-chapters/)。
